# TODO: Atlas 来信时延基准与优化

状态：第一轮实验和路由优化已完成，跨地区基准待补齐（2026-09-05）

已完成的固定地点实验、选用的 Exa fast 搜索和 Fireworks 优先路由、限制及回滚方式见 [实验记录](atlas-latency-2026-09-05.md)。以下矩阵仍是待完成的验证范围，不代表已有跨地区 P50/P95 结果。重测排序和搜索引擎时以当前路由为基线；优先用 `OPENROUTER_DESCRIPTION_PROVIDER_SORT` 单独控制来信路径。

优先级：高

约束：Atlas 每封来信都必须真实检索资料；不缓存或复用来信正文。

## 问题

Atlas 已经使用 SSE 流式返回，但用户仍需要等待较长时间才看到第一段文字。现有日志可以区分地理与街景上下文、OpenRouter 建立响应、上游首个 token、用户可见首字和完整生成，下一步需要用稳定样本持续记录 P50/P90/P95。

## 基准矩阵

- 每轮至少覆盖 6 个地区：东亚、欧洲、中东、北美、南美、非洲或大洋洲。
- 同一个地点连续请求至少 2 次，确认没有正文缓存，并观察搜索服务的冷热差异。
- 分别测试中文和英文；标准来信与“再多讲讲”各至少 3 次。
- 对比 `OPENROUTER_PROVIDER_SORT=latency`、`throughput` 和 `off`。
- 在保持真实资料检索的前提下，对比 Web Search `auto`、原生搜索和 Exa；记录搜索请求数、引用数量和事实质量。
- 语音模式单独统计：用户停说、转写完成、工具选择、街景准备、首个回复文本和首段音频。

## 必须记录的阶段

1. `lookup_ms`：坐标反查与 panorama 定位。
2. `context_ms`：反向地理信息与街景图片准备。
3. `upstream_open_ms`：发出 OpenRouter 请求到收到流式响应头。
4. `upstream_first_delta_ms`：发出请求到上游首个文本 token。
5. `visible_first_delta_ms`：发出请求到通过语言门禁并送达浏览器的首段文字。
6. `generation_tail_ms`：用户可见首字到完整来信。
7. `total_ms`：描述请求开始到 `done` 事件。
8. `web_search_requests`、引用数量、正文字符数、段落数和成功率。

## 初步目标

- 标准来信 `visible_first_delta_ms`：P50 小于 6 秒，P95 小于 10 秒。
- 标准来信 `total_ms`：P50 小于 12 秒，P95 小于 20 秒。
- 地理与街景 `context_ms`：P95 小于 1.5 秒。
- Web Search 每封来信至少执行 1 次，同时避免重复工具轮次。
- 同一地点连续生成的正文不得相同。
- 延迟优化不得降低语言一致性、视觉依据、引用覆盖率或历史事实准确度。

## 后续优化候选

- 在地理信息和街景准备完成后，减少送入模型的重复上下文与图片体积。
- 评估更快且支持视觉与原生搜索的模型，并与当前模型做盲测。
- 检查 Web Search 的 provider/engine 长尾，优先使用软排序，避免硬过滤导致无可用端点。
- 让地点身份确认与搜索查询构造更稳定，减少模型在同名地点上的额外推理和错误资料。
- 为生产日志增加可聚合的结构化 trace id，并建立按阶段统计脚本或面板。
